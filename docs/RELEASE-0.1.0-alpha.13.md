# 0.1.0-alpha.13：长历史分段压缩、断点续接与记忆保存

上版在某段结果被拒绝后没有保留已完成草稿，且把截断、空正文、工具调用和超长摘要混成同一错误。新版分别说明原因；默认输出上限由4096调整为8192 token，可选4096/8192/16384，服务商需支持相应参数。旧截图不能确定报告者当时具体命中了哪一项，真实模型质量与限额仍需实际使用验证。

- 默认“保留各段摘要”：每段独立总结，1–4路并发（默认3）；全部段落按顺序进入压缩后的聊天上下文，同时各存一条记忆。可切换“逐段合并为一份”，该方式依赖前文结果、保持顺序请求，最后保存一条记忆。
- 自定义压缩提示词：可指定第一人称、称呼、风格和重点。不会自动搬入整份聊天提示词/世界书，避免超限；需要的身份与重点请写在此处。历史内容仍按引用资料处理，没有工具权限。
- 每段成功后先存本机草稿再继续请求；并发完成乱序也按原段号保存。请求失败停止启动新段，已在途成功结果仍保存。刷新后恢复进度，继续只请求未完成段；不自动重试，暂停的在途请求可能已经计费。
- 原聊天发生改变时旧草稿不能覆盖新消息。模式、片段大小和提示词在已有进度时锁定；需要修改可明确清除草稿后重做。输出上限和并发数可在暂停后调整。
- 全部完成并经人类核对应用后，聊天、分段记忆和一个完整原文备份窗口在同一事务提交，不产生N个分支。分段标题内的人工修改同步存入对应记忆，仍可撤销最近一次压缩。
- 人类确认的多段摘要合计上限为1,048,576字符；单份摘要（自行填写或累计合并）与AI工具摘要仍保持65,536字符上限。字符不等于token，多段摘要本身仍可能超过较小模型容量，请结合当前模型核对。
- 未完成草稿只存本机，尚未写入记忆或聊天，也不包含API密钥；不随完整聊天备份导出，清除网站数据会丢失。需要离开页面可先暂停，修改完成的文字后点击保存草稿。

验证：72项逻辑测试通过；根路径和子路径生产构建、浏览器8,000条消息/89段/并发3路通过。模拟第5段截断时保留7个已成功结果，刷新后只补82个缺段、无重复成功段，最终89条记忆与一个原文窗口一致，人工修改/保存草稿/压缩后续聊/四种屏幕宽度通过。既有分支、取消、回退及AI工具压缩回归通过。测试使用合成历史与模拟模型接口，没有代用用户私聊或调用收费模型。
